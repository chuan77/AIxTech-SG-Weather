# Theming

`frontend/src/theme/` (registry in `themes.ts`, `ThemeContext.tsx`) sets `data-theme` on `<html>` and persists the choice in `localStorage` (`weather-theme`). Palettes are CSS-variable blocks in `frontend/src/index.css`.

- `tailwind.config.js` maps `white` to `rgb(var(--ink) / <alpha-value>)`, so every `text-white/…`, `border-white/…` and `bg-white/…` class follows the theme. Light themes set `--ink` to a dark colour. For something that must stay literally white (for example icons on the map's dark buttons) use `text-[#fff]`.
- `rounded-card` (radius from `--card-radius`) marks every themeable panel. Themes style it through `[data-theme='…'] .rounded-card`.
- Each theme in `themes.ts` also names its map basemap (`voyager`, `dark_all`, `light_all`).
- Every theme block also sets `--popover-bg`, the opaque surface for pop-up lists, applied with the `app-popover` class (the add form's town list). Translucent `bg-white/…` lets the cards beneath show through, so don't use it for pop-ups.
- To add a theme: a `[data-theme='…']` block in `index.css` plus an entry in `THEMES`.
- Every theme block also sets the rain station colours (spec 011, `.rain-mark` in `index.css`; the markup in `rainMarker.ts` carries no colour): `--rain-outline`, `--rain-dry`, `--rain-light`, `--rain-moderate`, `--rain-heavy` and `--rain-missing`. Levels differ by size and shape as well as colour (dry 10 px ring; light, moderate, heavy 14, 18, 24 px drops, heavy with a 3 px outline; "no reading" a dashed 14 px ring with a dash; a partial total adds a 9 px `--rain-outline` badge ringed in `--map-control-bg`), so no level relies on colour alone. The outline carries the 3:1 against the basemap: dark ink on light basemaps (`#0b2350`, or the theme's own ink on Pastel Sticker and Neo-Memphis), pale `#cfefff` on dark ones. Heavy must stand out most in every theme: the darkest drop on light basemaps and a saturated violet (`#b44bff`) on dark ones, never a pale or white fill. Ratios noted beside each value are against nominal basemap colours (CARTO tiles need a key to sample); `scripts/e2e/rain-view.sh themes` re-checks them in the browser.
- Every theme block also sets the temperature and wind label colours (spec 015, `.tw-mark` in `index.css`; the markup in `tempWindMarker.ts` carries no colour): `--tw-label-bg`, `--tw-label-text`, `--tw-label-border`, `--tw-arrow` and `--tw-missing`. Each station is an **opaque** pill, so its text never depends on the basemap: the temperature (`--tw-label-text`) and the muted "–°" and crossed-out no-wind glyph (`--tw-missing`) must reach 4.5:1 on `--tw-label-bg`, the arrow 3:1, and the pill (its fill or its `--tw-label-border` outline) 3:1 against the theme's basemap. Strength is the arrow's size (14, 18, 22 px for light, moderate, strong, strong also with a heavier stroke), calm is the word "calm", and no reading is a solid struck-through glyph, so nothing relies on colour. Don't reuse `--lightning` for the arrow: the lightning marks share the map. The measured ratios are noted beside each theme's values; `scripts/e2e/temp-wind.sh themes` re-checks them in the browser, at 375 and 1280 px.
- Every theme block also sets `--lightning` and `--lightning-outline`, the fill and outline of the bolt-shaped lightning strike marks on the map (`.strike-mark` in `index.css`; the markup in `strikeMarker.ts` carries no colour). Only the fill fades with a strike's age, down to `--lightning-fill-floor` (default 0.25; a theme may set it). The outline never fades, so it alone must give 3:1 contrast against the theme's basemap: a dark ink on light basemaps, and the bright lightning colour itself on dark ones (Midnight Radar, Singapore Sky). The measured ratios are noted beside each value. Where strikes crowd, the map shows a round group mark instead (spec 009, `.strike-group` in `index.css`, markup in `groupMarker.ts`): a solid `--lightning` core with a small bolt and the strike count, an age tab ("now", "2m" … "59m") and a halo. Only the halo's fill fades with the newest strike's age, using the same `--lightning-fill-floor` rule as the bolts; the core, the tab and the `--lightning-outline` ring never fade. The count and age text use `--lightning-ink`, which every theme sets to give at least 4.5:1 on its own `--lightning` (ratios noted beside each value: 5.2:1 to 15.2:1). Group marks are 28, 32 or 36 px by count, smaller than the 40 px grouping radius, so neighbours rarely cover each other. The map's overlay buttons, the lightning status strip and Leaflet's zoom buttons use the `map-control` class, which reads `--map-control-bg`, `--map-control-bg-hover`, `--map-control-border` and `--map-control-text` from the theme. Each theme picks values that stay legible on its own basemap.
- `--ink-muted` is secondary text (timestamps, labels, helper lines), used as `text-ink-muted`. Each theme sets it to the lowest ink strength that still clears 4.5:1 on its panels, including hover (12%) and selected (20%) fills. Don't use `text-white/…` below 85; use `text-ink-muted` instead.
- `--focus-ring` is the solid 2px focus outline for every focusable element (white on Apple and Glass, cyan on Radar, purple on Sticker, black on Memphis).
- **Fixed colours outside the theme (spec 014).** Browsers read the manifest's `theme_color` and `background_color` and the `<meta name="theme-color">` before any CSS, and `frontend/public/offline.html` is the only file the offline helper keeps, so it can't load `index.css`. These use literal copies of the `apple` theme: `#202a36` (its darkest sky stop) for backgrounds, `#ffffff` for text and `rgba(255, 255, 255, 0.85)` for secondary text (14.9:1 and about 11:1). They don't follow theme switches. If the default theme's darkest sky colour changes, update `frontend/public/manifest.webmanifest`, the `theme-color` meta in `frontend/index.html`, `frontend/public/offline.html` and the icon background in `frontend/icons/lepak-mark.svg` and `frontend/public/favicon.svg` (then re-run `scripts/icons/render-icons.sh`). This is a justified deviation from constitution Principle V, recorded in `specs/014-installable-app/plan.md`. The iPhone Add to Home Screen button and its tip are ordinary panels and use theme classes (`rounded-card`, `app-popover`, `text-white`, `text-ink-muted`) as usual.
- `apple` is the default and the reference design. It follows Apple's current design language and changes only in a deliberate theming change (constitution Principle V), never as a side effect of other work. Its sky was darkened in Nov 2026 so text meets WCAG AA contrast.
- Gauge fills come from `--scale-psi`, `--scale-wbgt` and `--scale-uv`, applied by `ScaleBar` as the `scale-bar--psi`, `scale-bar--wbgt` and `scale-bar--uv` classes. The defaults reproduce the original Tailwind gradients. The UV tile's hourly bars (`.uv-bar`) sample `--scale-uv` too: each bar shows a 1/22-wide slice of the gradient centred on its value (an inline `background-position-x` from `uvBarPosition`), so a theme's UV gradient colours both the gauge and the bars, and banded gradients (Singapore Sky) give each bar one band colour. Heat-stress labels carry `heat-tone heat-tone--{low|moderate|high|unknown}`, which only Singapore Sky styles.
- `data-sky` (`storm`, `haze`, `heat` or `calm`) is set on `<html>` by `Layout` from `skyState()` in `src/theme/sky.ts`, whatever the theme. Only `singapore` reads it. A theme that reacts to data must pass contrast in every state, not just the default.
